# SWORD‑le Pipeline

Tools for the generation of the SWORD Localy Expertised database for SWOT

## Overview

**sword-le** is a geospatial processing pipeline designed to industrialize the selection, correction, and merging reaches coming from:

1. **SWORD** : SWORD Explorer(https://www.swordexplorer.com/)

2. **REPLACEMENT dataset** :  BD TOPAGE [https://www.data.gouv.fr/datasets/bd-topage-r](https://www.data.gouv.fr/datasets/bd-topage-r)
=> A manual pre‑selection step is required to choose the relevant TOPAGE reaches to use for each study area. These selected reaches will be used to correct or replace corresponding SWORD reaches inside the mask.

3. **POLYGON mask** :  defining the study area is applied to filter and process the reaches


## Environment & Dependencies

### Operating System

* **Linux** (tested)

### Python Environment

The pipeline runs in a dedicated Conda environment defined in `swordle_upgrade.yml`

* Python **3.13**
* Main libraries: `geopandas`, `shapely`, `fiona`, `pyproj`, `geopy`, `matplotlib`, `tqdm`

### Environment Setup

```bash
conda env create -f swordle_upgrade.yml
conda activate swordle_upgrade
```

---

## Input Data Requirements

* All input shapefiles **must be in EPSG:4326**
* Valid geometries (LineString / MultiLineString)


## Execution

The pipeline is executed from the command line.

### Example

```bash
python swordle_prod_upgrade.py \
    --mask /path/to/mask.shp \
    --sword /path/to/sword_reaches.shp \
    --replacement /path/to/topage_extraction.shp \
    --default-attributes /path/to/default_attributes.json \
    --results /path/to/output_folder/
```

### Argument Description

* `--mask` : Polygon mask defining the study area
* `--sword` : Input SWORD reaches
* `--replacement` : reaches used to correct or replace SWORD segments
* `--default-attributes` : JSON file with default attributes depending on the version of SWORD
* `--results` : Output directory

## Outputs

The pipeline automatically generates multiple shapefiles for diagnostics and final delivery.

### Diagnostic Shapefiles

* `test_rep_masked_out.shp`
* `test_rep_masked_in.shp`
* `test_src_masked_out.shp`
* `test_src_up_reach.shp`
* `test_src_dw_reach.shp`
* `test_rep_keeped.shp`
* `test_src_keeped.shp`
* `test_points.shp`

These layers help analyze reach selection, masking effects, and correction logic.

### Corrected Reaches

* `test_new_up_reach.shp`
* `test_new_dw_reach.shp`

Corrected upstream and downstream reaches generated by the pipeline.

### Final Output

* `test_complete.shp`

**Final deliverable** combining:

* Corrected upstream and downstream reaches
* Internal valid reaches
* All remaining valid SWORD reaches
